# День 25 — длинные диалоги с RAG и памятью задачи

## Подготовка

Соберите `cargo build`. Для живого прогона нужен `NEURALDEEP_API_KEY`; ключ не записывается в отчёт.
Офлайн-тесты используют локальные mock-серверы и не требуют ключа или внешней сети.

Создайте отдельный временный каталог состояния и используйте его для всех команд эксперимента:

```bash
export XDG_STATE_HOME="$(mktemp -d)"
target/debug/agi rag add README.md projetcDocs/invariants_testing.md projetcDocs/llm_docs.md \
  projetcDocs/memory_layers.md projetcDocs/memory_testing.md \
  projetcDocs/task_state_testing.md projetcDocs/task_transitions_testing.md
target/debug/agi rag status
```

Материалы `projetcDocs/rag` служат методической основой; PNG без OCR не индексируются.
Не меняйте корпус во время оценки. Для уже загруженных документов выполните refresh; после смены
модели embeddings или endpoint — reindex. Текущий индекс оценки не изменяется; чаты создаются в
отдельном временном каталоге, удаляемом после прогона.

## Ручная проверка интерфейса

```text
/rag chat on
Цель: разобраться в восстановлении чатов agi. Облачное хранение запрещено. Где хранится история?
Под «сессией» я понимаю чат с UUID. Как восстановить её после перезапуска?
/rag chat state
А из уже открытого приложения?
Исправляю ограничение: ручное редактирование Markdown разрешено. Где хранится долговременная память?
/rag chat state
Какой утверждённый бюджет проекта agi на 2030 год?
```

У каждого ответа есть блок источников. Ссылки `[n]` соответствуют реальным цитатам и чанкам.
При недостатке сведений ответ содержит «не знаю», уточнение и явное отсутствие подтверждений.
Цель и актуальные условия сохраняются даже после такого отказа.

Проверьте `/rag off` и `/rag strict off`: пока режим активен, команды требуют `/rag chat off`.
После off память остаётся. reset очищает память без удаления истории; прежние условия не должны
автоматически восстанавливаться. `/clear` создаёт новый чат с пустой памятью и выключенным режимом.
Проверьте одинаковую работу в REPL и TUI. `/task` использует прежний отдельный цикл выполнения.

## Профиль поиска для оценки

Оценка использует structure, top-K 20 → 4, rerank с порогом 0.20. Этот профиль выбран после
промахов similarity на данном корпусе; исходный частичный результат сохранён в
`day25_rag_baseline_similarity.md`. Порог не является универсальной рекомендацией и оценка на
новом корпусе требует отдельного набора. Настройки обычных чатов и режимов дней 23–24 не меняются.
Для воспроизведения профиля в интерактивном чате:

```text
/rag chat on
/rag filter rerank
/rag topk 20 4
/rag threshold rerank 0.20
```

Порог оценки можно явно задать через `--rerank-threshold VALUE` в shell или после `/rag evaluate day25`.

## Два сценария

Набор `day25_rag_eval.json` содержит два сценария по 12 вопросов с ожиданиями ответа и памяти.

1. Хранение и восстановление: локальная история, термин «сессия», короткие продолжения, два ограничения,
   отвлечение, явная отмена одного ограничения, неизвестный бюджет и возвращение к исходной цели.
2. Настройка RAG: локальный индекс, термин «порог», top-K, отвлечение, изменение лимита 4 → 3,
   неизвестный SLA и замена определения similarity → rerank.

Окно истории — 4 сообщения, поэтому начальная цель быстро исчезает из переписки, доступной модели.
На седьмом ходе каждого сценария чат загружается из SQLite: память, история и настройки должны совпасть.
Для каждого хода сохраняются исходный вопрос, самостоятельный запрос, результаты поиска,
полные итоговые чанки, память до/после, ответ, цитаты, usage и вердикт судьи.

```bash
target/debug/agi rag evaluate --suite day25 --eval projetcDocs/day25_rag_eval.json \
  --report projetcDocs/day25_rag_answers.md
```

Из чата: `/rag evaluate day25`; отчёт — `/rag report day25`. Можно указать иной JSON-набор:
`/rag evaluate day25 /путь/набор.json`. В TUI Ctrl+C отменяет оценку и сохраняет частичный отчёт.
В shell прерывание может оставить последний атомарно записанный частичный отчёт.

Судья отдельно оценивает сохранение цели, ограничений, терминов, самостоятельность запроса,
правильность ответа, подтверждение фактов цитатами и корректность отказа. Ошибка судьи не становится
положительной оценкой. Неудачная генерация прекращает зависимые ходы текущего сценария; второй сценарий
проверяется отдельно. Если автоматические критерии не пройдены, команда завершается ошибкой с путём отчёта.

## Приёмка

Оба сценария завершены, 24/24 автоматических проверок пройдены. На каждом ходе цель и актуальные
условия сохранены, при исправлении старое условие заменено; все ответы содержат блок источников.
Каждая приведённая цитата подлинна, каждый существенный документальный факт подтверждён цитатой.
Оба отрицательных случая дают отказ без выдуманных источников.

После чтения всех ответов заполните раздел ручной проверки отчёта: цель/условия, источники,
смысл цитат и расхождения с судьёй. Оценки судьи не подменяют фактические результаты.
