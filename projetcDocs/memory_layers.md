# Модель памяти агента

В `agi` память разделена на три слоя. Каждый слой имеет собственное назначение, срок жизни и способ сохранения. Сообщения не переносятся между слоями автоматически: пользователь явно решает, какие данные должны пережить текущий диалог или задачу.

| Слой | Что в него попадает | Хранилище | Срок жизни |
| --- | --- | --- | --- |
| Краткосрочный | Сообщения текущего диалога, резюме и Sticky Facts | SQLite | Текущий чат |
| Рабочий | Цель задачи, ограничения, план, текущий шаг и промежуточные результаты | SQLite, таблица `working_memory` | Текущая задача/чат |
| Долговременный | Профиль пользователя, решения и знания | Markdown | Между чатами и перезапусками |

Это соответствует архитектуре лекции: профиль загружается отдельно, сборщик объединяет его с состоянием текущей задачи и запросом, а в prompt попадают только нужные данные. Суммаризация диалога не затрагивает профиль и рабочую память.

## Долговременная память и профиль

Markdown-файлы находятся в каталоге `memory` рядом с `chats.sqlite3`:

```text
memory/
├── profiles/
│   ├── default.md
│   ├── beginner.md
│   └── senior.md
├── decisions/
│   └── <имя>.md
└── knowledge/
    └── <имя>.md
```

Каждый именованный профиль повторяет структуру со слайда 11:

```markdown
# Профиль пользователя

## Style
Краткость, тон, язык и необходимость примеров.

## Constraints
Постоянные ограничения пользователя и допустимые технологии.

## Context
Роль, опыт и устойчивый контекст пользователя.
```

Профиль `default` подключён в новых чатах по умолчанию; его отсутствие допустимо. Активный профиль выбирается отдельно для каждого чата и восстанавливается вместе с ним. Остальные профили, решения и знания сохраняются независимо. Ручные изменения Markdown подхватываются перед следующим запросом.

При первом обращении к памяти старый файл `memory/profile.md` автоматически переносится в `memory/profiles/default.md`. Если оба файла уже существуют, `default.md` имеет приоритет, а старый файл остаётся нетронутой резервной копией.

## Команды

```text
/memory
/memory short
/memory working
/memory working set <ключ> <текст>
/memory working delete <ключ>
/memory working clear
/memory profile init
/memory profile list
/memory profile create <имя>
/memory profile show [имя]
/memory profile set [имя] <style|constraints|context> <текст>
/memory profile delete <имя>
/memory long
/memory long set <decision|knowledge> <имя> <текст>
/memory long show <decision|knowledge> <имя>
/memory long delete <decision|knowledge> <имя>
/memory use profile [имя]
/memory unuse profile
/memory use <decision|knowledge> <имя>
/memory unuse <decision|knowledge> <имя>
/memory context
```

`profile init`, `profile show`, `profile set` и `use profile` без имени сохраняют совместимость с прежним интерфейсом и работают с активным профилем либо `default`. Создание профиля не переключает текущий чат. `/memory profile list` помечает активный профиль символом `*`.

`/memory context` показывает память, которая будет добавлена к следующему запросу, включая имя активного профиля. Это позволяет проверить выбор данных до обращения к модели. Команды изменения памяти сохраняют результат сразу, поэтому чат с рабочей памятью или выбранным профилем можно восстановить даже до первого ответа AI.

Рабочая память ограничена 50 записями: ключ до 64 символов без пробелов, значение до 1000 символов. Общий объём подключённой Markdown-памяти не может превышать 32 КиБ. При превышении лимита или отсутствии выбранного файла запрос не отправляется, данные не усекаются.

## Как память влияет на запрос

Сборщик формирует сообщения в следующем порядке:

1. Основная системная инструкция агента.
2. Профиль пользователя.
3. Выбранные решения и знания.
4. Рабочая память текущей задачи.
5. Резюме и история текущего диалога.
6. Новый вопрос пользователя.

Главный и дочерние агенты получают один снимок памяти. Блоки имеют явные заголовки слоя, поэтому модель различает пользовательский профиль, сведения задачи и историю разговора. Текст памяти не является командой управления приложением.

`/clear` начинает новый чат с пустой краткосрочной и рабочей памятью и активным профилем `default`. Решения и знания нужно выбрать снова. Checkpoint сохраняет рабочую память, имя профиля и список подключений; ветки получают независимые копии выбора. Сами Markdown-файлы остаются общими и не откатываются вместе с checkpoint.

## Проверка влияния на ответы

Для воспроизводимого эксперимента задайте один вопрос в независимых чатах.

### 1. Ответ без профиля

```text
/memory unuse profile
Объясни dependency injection
```

Ожидание: общий ответ без привязки к опыту и стеку пользователя.

### 2. Профили начинающего и опытного разработчиков

```text
/memory profile create beginner
/memory profile set beginner style Объясняй простыми словами и показывай короткий пример
/memory profile set beginner context Я начинающий Kotlin-разработчик
/memory profile create senior
/memory profile set senior style Используй профессиональную терминологию и будь краток
/memory profile set senior context Я опытный Rust-разработчик
/memory use profile beginner
Объясни dependency injection
/memory use profile senior
Объясни dependency injection
```

Ожидание: первый ответ содержит простое объяснение и базовый Kotlin-пример, второй рассчитан на опытного Rust-разработчика. `/memory context` перед каждым вопросом показывает имя и содержимое выбранного профиля.

### 3. Профиль и данные текущей задачи

```text
/memory working set goal Выбрать DI для Android-приложения
/memory working set team Команда из 4 разработчиков
/memory working set deadline Две недели
/memory long set decision stack Проект использует Kotlin и Jetpack Compose
/memory use decision stack
/memory context
Объясни dependency injection
```

Ожидание: ответ учитывает Kotlin, размер команды, срок и выбранное решение. После перезапуска восстановите чат по UUID и выполните `/memory context`: рабочие данные и подключение должны сохраниться.

Автоматические тесты используют локальный mock-сервер и проверяют фактически отправленные сообщения, изоляцию слоёв, сохранение и ошибки. Они не оценивают качество генерации. Для сравнения реальных формулировок нужен доступный `NEURALDEEP_API_KEY`.

Полная пошаговая процедура приведена в [memory_testing.md](memory_testing.md).
