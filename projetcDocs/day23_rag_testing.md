# День 23 — проверка фильтрации, reranker и rewrite

## Проверка через интерфейс agi

Запустите текущую версию из корня проекта: `cargo run` или `./target/debug/agi`. При запуске просто `agi` убедитесь, что
это новая сборка. Все следующие команды вводятся внутри приложения, по одной строке. Для общения, rewrite, reranker и
LLM-судьи нужен заданный до запуска `NEURALDEEP_API_KEY`.

Сначала загрузите корпус:

```text
/rag add README.md
/rag add projetcDocs/invariants_testing.md
/rag add projetcDocs/llm_docs.md
/rag add projetcDocs/memory_layers.md
/rag add projetcDocs/memory_testing.md
/rag add projetcDocs/task_state_testing.md
/rag add projetcDocs/task_transitions_testing.md
/rag list
/rag status
```

Добавление документов повторно обновляет их в индексе. Для воспроизводимости учитывайте, что ранее добавленные
посторонние документы тоже участвуют в поиске. Если статус показывает старые векторы, выполните `/rag reindex`; если
изменились файлы корпуса — `/rag refresh`.

Перед каждым ручным сравнением создайте новый чат и задайте общие параметры:

```text
/clear
/rag on
/rag strategy structure
/rag topk 12 4
```

`/clear` создаёт новый чат с настройками по умолчанию. Поэтому настройки выбранного режима задавайте после `/clear`,
затем задавайте один и тот же вопрос.

| Режим                | Настройка фильтра        | Настройка rewrite  | Дополнительно                    |
|----------------------|--------------------------|--------------------|----------------------------------|
| Исходный RAG         | `/rag filter off`        | `/rag rewrite off` | —                                |
| Только rewrite       | `/rag filter off`        | `/rag rewrite on`  | —                                |
| Similarity           | `/rag filter similarity` | `/rag rewrite off` | `/rag threshold similarity 0.50` |
| Similarity + rewrite | `/rag filter similarity` | `/rag rewrite on`  | `/rag threshold similarity 0.50` |
| Reranker             | `/rag filter rerank`     | `/rag rewrite off` | `/rag threshold rerank 0.50`     |
| Reranker + rewrite   | `/rag filter rerank`     | `/rag rewrite on`  | `/rag threshold rerank 0.50`     |

В каждом режиме проверьте поиск, затем обычный ответ:

```text
/rag status
/rag search Где хранится локальный индекс RAG и отделён ли он от истории чатов?
Где хранится локальный индекс RAG и отделён ли он от истории чатов?
```

Ожидание: `rag.sqlite3` в каталоге состояния приложения, отдельно от истории чатов. В поиске видны исходный и поисковый
запросы, не более 12 кандидатов и не более 4 итоговых фрагментов. В режиме reranker выводится дополнительная оценка
rerank. При rewrite поисковый запрос может измениться, а вопрос пользователя в переписке остаётся исходным. В ответе
проверяйте факты и ссылки `[n]`; автоматически добавленный список источников не заменяет ссылку модели.

Другие вопросы для сравнения: «Как восстановить сохранённый чат по UUID?», «Переключил embeddings на другой сервер, а
поиск ругается на старые чанки. Что делать?», «Какой SLA гарантирует agi для восстановления rag.sqlite3 после аварии
сервера?». Для последнего сведений в корпусе нет — модель должна признать недостаточность данных.

Проверьте полное отсечение отдельно:

```text
/rag filter similarity
/rag rewrite off
/rag threshold similarity 1
/rag search Какой SLA гарантирует agi для восстановления rag.sqlite3 после аварии сервера?
Какой SLA гарантирует agi для восстановления rag.sqlite3 после аварии сервера?
/rag threshold similarity 0.50
```

Ожидание: итоговый контекст пуст, ответ сообщает о недостаточности документального контекста и не содержит добавленных
приложением источников. Затем проверьте ошибки настройки: `/rag topk 2 5`, `/rag threshold rerank 1.5`. Команды должны
сообщить ошибку, а `/rag status` — показать прежние параметры.

Чтобы проверить сохранение настроек, получите один успешный ответ, переключитесь через `/chat` в другой чат и вернитесь.
`/rag status` должен показывать параметры проверяемого чата.

Полная автоматическая проверка тоже запускается из интерфейса:

```text
/rag evaluate day23
/rag report day23
```

Она сама перебирает шесть режимов, подбирает пороги и оценивает ответы; параметры текущего чата на эксперимент не
влияют. В TUI отчёт прокручивается стрелками и `PgUp`/`PgDn`, закрывается `Esc`. `Ctrl+C` отменяет проверку. При
таймауте или ошибке откройте частичный отчёт через `/rag report day23`; полный результат имеет статус «завершён».

## Подготовка

Соберите актуальный корпус из семи файлов, используемых для Дней 21–22:

```bash
agi rag add README.md projetcDocs/invariants_testing.md projetcDocs/llm_docs.md \
  projetcDocs/memory_layers.md projetcDocs/memory_testing.md \
  projetcDocs/task_state_testing.md projetcDocs/task_transitions_testing.md
agi rag status
```

Для чистого эксперимента запускайте shell-команды с отдельным `XDG_STATE_HOME`, например `/tmp/agi-day23-state`. Иначе в
поиске участвуют все ранее загруженные документы. При смене модели эмбеддингов выполните `agi rag reindex`. Ключ
передаётся только через `NEURALDEEP_API_KEY`; не вставляйте его в команды, файлы и отчёт.

Не меняйте корпус во время эксперимента. В отчёте сохраняются список источников, fingerprint файлов и хеш набора
вопросов. Настройка порогов не изменяет настройки пользовательских чатов.

## Режимы

Поиск использует cosine similarity нормализованных векторов. Затем выполняется один из этапов: `off`, `similarity` или
`rerank`. В `rerank` весь набор кандидатов отправляется в NeuralDeep `bge-reranker`, без предварительного
similarity-порога. Порог включительный: оценка, равная порогу, проходит.

Все прошедшие фрагменты участвуют в отборе по разделам, top-K и бюджету 6000 символов. Отброшенные фрагменты не
возвращаются, даже если контекст пуст. Список источников содержит только итоговые фрагменты.

```text
/rag on
/rag filter similarity
/rag threshold similarity 0.35
/rag topk 12 4
/rag rewrite on
/rag search Как восстановить чат?
/rag status
```

Другой второй этап: `/rag filter rerank`, `/rag threshold rerank 0.50`. Выключение: `/rag filter off`,
`/rag rewrite off`. Настройки общие для REPL и TUI и сохраняются в текущем чате.

Переписывание выполняется отдельным структурированным запросом: текущий вопрос → поисковый запрос. История, память и
документы в rewrite не передаются. Исходный вопрос остаётся вопросом для генерации ответа. Rewrite имеет таймаут 30
секунд; reranker — 30 секунд; судья — 60 секунд. Ошибки rewrite/reranker останавливают операцию без скрытого fallback. В
TUI `Ctrl+C` отменяет фоновую проверку; завершённые вопросы остаются в частичном отчёте.

## Сравнение

Внутри приложения:

```text
/rag evaluate day23
/rag report day23
```

Из shell:

```bash
agi rag evaluate --suite day23 --eval projetcDocs/day23_rag_eval.json \
  --report projetcDocs/day23_rag_comparison.md
```

Сравниваются шесть режимов: исходный RAG, только rewrite, similarity-фильтр, similarity + rewrite, reranker, reranker +
rewrite. Top-K для всех: 12 → 4, стратегия `structure`, температура ответа и судьи 0. Каждый ответ получается в новом
пустом чате. Поиск и rewrite переиспользуются между режимами одного вопроса; генерация и оценка выполняются отдельно.
Для эксперимента используются обычные непотоковые запросы с теми же сообщениями RAG; потоковый вывод обычного чата
сохраняется. Лимит ответа — 10000 токенов, таймаут генерации — 120 секунд.

Канонический набор содержит 10 вопросов независимой проверки и 5 для настройки: три разговорные переформулировки и два
вопроса о сведениях, отсутствующих в документах. Эталоны определяются источником и anchor, а не просто совпадением имени
файла.

Подбор порогов использует только пять вопросов настройки, без rewrite: similarity 0.20/0.35/0.50/0.65; reranker
0.25/0.50/0.75. Выбирается порог, сохраняющий хотя бы один эталонный фрагмент для каждого положительного вопроса и
полностью отсекающий контекст для максимального числа отрицательных. При равенстве выбирается меньший порог. Если
подходящего нет, остаётся исходное значение 0.35 или 0.50. Затем пороги фиксируются для всех шести режимов.

Полный запуск требует 5 embeddings + 5 rerank для настройки и 255 запросов основной проверки: 30 embeddings, 15 rewrite,
30 rerank, 90 генераций и 90 оценок судьи. Загрузка корпуса выполняется отдельно. Точная стоимость зависит от
провайдера; отчёт показывает доступный usage, а не выдуманные токены reranker.

Отчёт сохраняется после настройки порогов, каждого режима и каждого полностью завершённого вопроса через атомарную
замену. Отмена или ошибка оставляет статус «частичный»; автоматического возобновления нет. Повторный запуск пересоздаёт
отчёт.

## Оценка

Hit@K и MRR@K показывают попадание эталонного фрагмента в итоговый контекст. На отрицательных вопросах измеряется доля
полностью отсечённого контекста. При пустом контексте генератор получает инструкцию признать недостаточность данных.

LLM-судья получает вопрос, эталон, итоговый контекст и ответ без автоматического списка источников. Название режима и
оценки поиска ему не передаются. Он оценивает правильность, опору утверждений на контекст и релевантность контекста по
шкале 0–2, а также корректность отказа для отрицательных примеров. Неприменимые оценки имеют `null`. Ошибки судьи не
считаются нулём и исключаются из средних.

Проверьте обоснования судьи вручную: модель оценки совпадает с моделью ответа, и её баллы не являются объективной
гарантией. Наличие `[n]` и списка источников само по себе не подтверждает ответ. Результаты на вопросах настройки
отделены от независимой проверки; отрицательные примеры входят только в группу настройки.

Для сдачи приложите полный отчёт, выбранные пороги, сравнение метрик и 2–3 фактических примера различий. Укажите
ухудшения и дополнительные задержки. Если улучшения нет, опишите это прямо, не заменяя результат обещанием.

## Фактический прогон 30 сентября 2026

[Сохранённый отчёт](day23_rag_comparison.md) содержит реальный подбор порогов на пяти вопросах настройки. Similarity
0.50 сохранил 3/3 эталона и отсёк контекст для 1/2 отрицательных вопросов. Порог 0.65 отсёк оба отрицательных примера,
но оставил только 1/3 эталона. Reranker при 0.25 и 0.50 оставил 2/3 эталона и отсёк оба отрицательных примера; порог,
сохраняющий все три эталона, в проверенной сетке не найден.

Полный эксперимент остановился на таймауте query rewrite после предшествующего обрыва потокового ответа. Независимая
оценка 10 вопросов и вывод об улучшении качества ответов ещё не получены. Для окончательной сдачи повторите полный
запуск при доступном API; не выдавайте метрики настройки за независимую проверку.
