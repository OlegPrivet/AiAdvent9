# Ручное тестирование памяти в `agi`

Ниже приведены сценарии для установленной команды `agi`. Запустите приложение обычным способом:

```bash
agi
```

Команды вводятся непосредственно в открытом приложении. Для вопросов к агенту используется уже настроенный API-ключ.

## Тест 1. Просмотр трёх слоёв

Введите:

```text
/memory
```

Ожидаемый результат:

- показано количество сообщений краткосрочной памяти;
- показано количество записей рабочей памяти;
- показано количество профилей, решений и знаний;
- отображается имя активного профиля либо состояние `отключён`;
- указан каталог Markdown-памяти.

Затем выполните:

```text
/memory short
/memory working
/memory long
```

В новом чате краткосрочная и рабочая память должны быть пустыми. Долговременная память может содержать записи из
предыдущих чатов.

## Тест 2. Краткосрочная память текущего диалога

Введите два сообщения:

```text
Запомни тестовый код: ALPHA-731.
Какой тестовый код я назвал?
```

Ожидаемый ответ содержит `ALPHA-731`.

Проверьте сохранённый диалог:

```text
/memory short
```

Ожидаемый результат: команда показывает оба вопроса и ответы агента.

Начните новый чат:

```text
/clear
/memory short
```

Ожидаемый результат: краткосрочная память нового чата пуста. Если теперь спросить `Какой тестовый код я называл?`, агент
не должен извлекать `ALPHA-731` из предыдущего чата.

## Тест 3. Явное сохранение в рабочую память

Введите:

```text
/memory working set goal Проверить модель памяти агента
/memory working set plan Проверить сохранение, восстановление и влияние на ответ
/memory working set current Проверка рабочей памяти
/memory working
```

Ожидаемый результат:

```text
current = Проверка рабочей памяти
goal = Проверить модель памяти агента
plan = Проверить сохранение, восстановление и влияние на ответ
```

Проверьте подготовленный контекст:

```text
/memory context
```

Ожидаемый результат: записи находятся в отдельном блоке `РАБОЧАЯ ПАМЯТЬ ТЕКУЩЕЙ ЗАДАЧИ`.

Проверьте влияние на ответ:

```text
Какова цель текущей задачи и что сейчас проверяется?
```

Ответ должен учитывать `goal`, `plan` и `current`.

Убедитесь, что приложение не перенесло записи в историю автоматически:

```text
/memory short
```

В истории должен быть вопрос о цели задачи и ответ агента. Служебные команды `/memory working set` не должны
отображаться как сообщения диалога.

## Тест 4. Восстановление рабочей памяти

Завершите приложение:

```text
/exit
```

`agi` выведет готовую команду вида `agi --restore ...`. Скопируйте и выполните её в терминале.

После восстановления введите:

```text
/memory working
/memory context
```

Ожидаемый результат: `goal`, `plan` и `current` сохранились. История диалога также восстановилась, но отображается
отдельно от рабочей памяти.

## Тест 5. Удаление рабочей памяти

Введите:

```text
/memory working delete current
/memory working
```

Ожидаемый результат: `current` удалён, а `goal` и `plan` сохранены.

Затем очистите весь рабочий слой:

```text
/memory working clear
/memory working
/memory short
```

Ожидаемый результат:

- рабочая память пуста;
- история вопросов и ответов не удалена;
- приложение сообщает, что очистка рабочей памяти не изменяет историю.

## Тест 6. Явное подключение долговременного знания

Создайте знание с уникальным тестовым именем:

```text
/memory long set knowledge memory-test-731 В тестовом проекте кодовое имя хранилища — ORBIT.
/memory long
/memory context
```

Ожидаемый результат:

- `memory-test-731` присутствует в списке `Knowledge`;
- содержимое записи ещё отсутствует в `/memory context`, поскольку знание только сохранено, но не подключено.

Спросите агента:

```text
Какое кодовое имя у хранилища тестового проекта?
```

До подключения знания агент не должен знать правильный ответ `ORBIT`.

Подключите запись явно:

```text
/memory use knowledge memory-test-731
/memory context
```

Теперь контекст должен содержать отдельный блок `knowledge / memory-test-731` и значение `ORBIT`.

Повторите вопрос:

```text
Какое кодовое имя у хранилища тестового проекта?
```

Ожидаемый ответ содержит `ORBIT`. Это проверяет влияние выбранной долговременной памяти на ответ.

## Тест 7. Отключение знания

Введите:

```text
/memory unuse knowledge memory-test-731
/memory context
```

Ожидаемый результат: блок `knowledge / memory-test-731` исчез из контекста, но сама запись осталась в `/memory long`.

Снова подключите её:

```text
/memory use knowledge memory-test-731
```

Начните новый чат:

```text
/clear
/memory context
/memory long
```

Ожидаемый результат:

- знание осталось в общем Markdown-хранилище и отображается в `/memory long`;
- в новом чате оно не подключено и отсутствует в `/memory context`.

## Тест 8. Долговременное решение

Введите:

```text
/memory long set decision memory-storage Рабочую память проекта следует хранить в SQLite.
/memory use decision memory-storage
/memory context
```

Ожидаемый результат: контекст содержит отдельный блок `decision / memory-storage`.

Спросите:

```text
Где следует хранить рабочую память проекта?
```

Ожидаемый ответ: в SQLite.

Удалите решение:

```text
/memory long delete decision memory-storage
/memory long
/memory context
```

Ожидаемый результат: решение удалено из хранилища и больше не подключено к текущему чату.

## Тест 9. Несколько именованных профилей

Создайте два тестовых профиля и задайте им явно различающиеся правила:

```text
/memory profile create test-beginner-731
/memory profile set test-beginner-731 style Начинай ответ словом НОВИЧОК и объясняй простыми словами
/memory profile set test-beginner-731 constraints Отвечай одним предложением
/memory profile set test-beginner-731 context Пользователь только начинает изучать Rust
/memory profile create test-senior-731
/memory profile set test-senior-731 style Начинай ответ словом ЭКСПЕРТ и используй профессиональную терминологию
/memory profile set test-senior-731 constraints Отвечай одним предложением
/memory profile set test-senior-731 context Пользователь — опытный Rust-разработчик
/memory profile list
```

Ожидаемый результат: в списке присутствуют оба имени. Повторная команда `profile create` для того же имени должна
завершиться ошибкой и не перезаписать профиль.

Подключите профиль начинающего:

```text
/memory use profile test-beginner-731
/memory profile show
/memory context
Что такое владение в Rust?
```

Ожидаемый результат:

- `profile show` без имени показывает активный `test-beginner-731`;
- в `/memory context` есть блок `ПРОФИЛЬ / test-beginner-731`;
- ответ начинается словом `НОВИЧОК`, состоит примерно из одного предложения и использует простое объяснение.

В этом же чате переключитесь на второй профиль и задайте тот же вопрос:

```text
/memory use profile test-senior-731
/memory context
Что такое владение в Rust?
```

Ожидаемый результат: контекст содержит `ПРОФИЛЬ / test-senior-731`, а ответ начинается словом `ЭКСПЕРТ` и рассчитан на
опытного разработчика. Так проверяется, что профиль подключается автоматически к каждому обычному запросу: после
`use profile` его не нужно указывать в вопросе.

Завершите приложение командой `/exit`, выполните выведенную команду `agi --restore ...` и проверьте:

```text
/memory profile show
/memory context
```

Ожидаемый результат: восстановленный чат по-прежнему использует `test-senior-731`.

Теперь начните новый чат:

```text
/clear
/memory
/memory context
```

Ожидаемый результат: новый чат использует `default`, а не профиль `test-senior-731`. Именованные профили при этом
остаются в `/memory profile list`.

Отключите профиль и убедитесь, что его блок исчез:

```text
/memory unuse profile
/memory context
```

Ожидаемый результат: контекст больше не содержит блок профиля.

## Тест 10. Удаление профиля

Введите:

```text
/memory use profile test-beginner-731
/memory profile delete test-beginner-731
/memory
/memory profile list
```

Ожидаемый результат: профиль удалён из списка, а в текущем чате профиль автоматически отключён. Удаление одного профиля
не изменяет `test-senior-731`.

## Тест 11. Проверка трёх слоёв одновременно

Подготовьте данные:

```text
/memory use profile test-senior-731
/memory working set goal Подготовить пример Rust CLI
/memory long set decision test-format Результат должен быть одной командой
/memory use decision test-format
/memory context
```

Затем задайте вопрос:

```text
Предложи результат для текущей задачи.
```

Проверьте:

- профиль влияет на язык и стиль ответа;
- рабочая память сообщает цель текущей задачи;
- решение `test-format` задаёт формат результата;
- `/memory short` содержит диалог;
- `/memory working` содержит только данные текущей задачи;
- `/memory long` содержит общие Markdown-записи.

## Очистка тестовых данных

Удалите созданные этой инструкцией записи:

```text
/memory working clear
/memory long delete knowledge memory-test-731
/memory long delete decision test-format
/memory profile delete test-senior-731
```

Профиль `test-beginner-731` уже удалён в тесте 10. Эти команды не меняют пользовательский профиль `default`.

## Критерии успешного тестирования

Тестирование пройдено, если:

1. Диалог нового чата не содержит сообщения предыдущего чата.
2. Рабочая память сохраняется после `/exit` и восстановления чата.
3. Очистка рабочей памяти не удаляет историю диалога.
4. Новое знание не влияет на контекст до явного `/memory use`.
5. Подключённое знание меняет ответ агента, а `/memory unuse` убирает его из контекста.
6. Долговременные файлы остаются доступными в новых чатах, но решения и знания не подключаются автоматически.
7. Два именованных профиля дают различающиеся ответы на один вопрос.
8. Выбранное имя профиля сохраняется при восстановлении чата, а новый чат начинает с `default`.
9. `/memory context` показывает имя активного профиля, рабочую и выбранную долговременную память отдельными блоками.
