# День 13: проверка состояния задачи

Основа: лекция `week3_stream6_slides/week3_stream6_summary_and_transcript.md`, раздел 4; слайды 18 (этапы), 19
(состояние как данные), 21 (инъекция состояния) и 22 (пауза и продолжение).

## Запуск и полный цикл

Из корня проекта установите актуальную версию команды:

```bash
cargo install --path .
```

После изменений исходников повторите установку, чтобы команда `agi` использовала обновлённый код. Если приложение уже
запущено, завершите его через `/exit` и откройте заново.

В терминале с настроенным `NEURALDEEP_API_KEY` запустите:

```bash
agi
```

Установленную команду можно запускать из любого каталога. Следующие команды `/task ...` вводятся внутри `agi`. Для
демонстрации выберите текстовую задачу, которую агент способен выполнить без shell:

```text
/task start Подготовь описание сервиса заметок на русском: требования, REST API, три примера запросов и проверка согласованности.
```

Агент составляет план или задаёт вопросы. Ответьте на вопросы и выполните `/task`. Ожидаются `planning`, список шагов и
действие `/task approve`. Без утверждения запросы выполнения не отправляются.

```text
/task approve
```

Агент автоматически выполняет шаги и переходит в `validation`. Если проверка выявляет замечания, выполняются шаги
исправления. Успешная проверка переводит задачу в `done`. Статус виден в заголовке TUI и в выводе REPL. Проверка
относится к сгенерированному тексту; реального исполнения кода и тестов у агента нет.

## Пауза и перезапуск

1. Во время planning нажмите Ctrl+C. Проверьте `/task`: этап не изменился, указана пауза. `/task resume` возобновляет
   планирование.
2. На готовом плане используйте `/task pause`, затем `/task resume`: выполнение не начинается до `/task approve`.
3. Во время второго шага execution нажмите Ctrl+C или кнопку «⏸ Пауза». В TUI также можно набрать `/task pause` и нажать
   Enter. Проверьте, что первый шаг отмечен выполненным, второй остался текущим.
4. Выполните `/exit`, скопируйте напечатанный UUID и в терминале запустите `agi --restore <UUID>`, заменив `<UUID>` на
   идентификатор чата.
5. Открытие чата показывает сохранённое состояние без новых запросов. Выполните `/task resume`. Агент получает цель,
   утверждённый план, уточнения и результат первого шага; повторять объяснения не нужно.
6. Повторите прерывание во время validation. После продолжения повторяется проверка, выполненные шаги не запускаются
   заново.

Незавершённый потоковый ответ отбрасывается. Продолжение повторяет прерванный запрос с последней сохранённой границы
шага; восстановление посреди генерации отдельного токена не поддерживается. Закрытие приложения без `/exit` сохраняет
все ранее зафиксированные шаги; после открытия требуется `/task resume`.

В построчном REPL команды читаются между запросами. Во время автоматического выполнения прерывайте через Ctrl+C.
`/task pause` доступна на приглашении ввода.

## Ошибки, память и ограничения

- Ответы пользователя на уточнения сохраняются до API-запроса; отмена или ошибка не теряет ввод.
- Некорректное обновление состояния, запрещённый переход и ошибка сервиса останавливают цикл. После исправления причины
  используйте `/task resume`.
- Ошибка SQLite не должна оставлять половину обновления: ответ и состояние сохраняются вместе, дальнейшие запросы не
  запускаются.
- В Sliding Window старые сообщения могут исчезнуть; цель, план и результаты остаются в состоянии задачи. `/summarize`
  также не изменяет его.
- В Branching создайте checkpoint, откройте две ветки и измените задачу только в одной: состояние другой ветки не должно
  измениться.
- После 50 итераций одного запуска или трёх итераций без прогресса задача ставится на паузу. Новый запуск через
  `/task resume` сбрасывает счётчик.
- `/task start` не заменяет существующую задачу. Для следующей задачи используйте `/clear`; предыдущая остаётся в
  истории чатов.

## Автоматические проверки без внешнего API

Эти команды выполняются из корня репозитория, вне запущенного `agi`:

```bash
cargo test
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
```

Тесты используют локальный HTTP mock и временную SQLite. Покрыты полный цикл обоих интерфейсов, утверждение,
недопустимые переходы, исправления после проверки, уточнения, пауза на каждом незавершённом этапе, отмена активного
запроса, запоздавшие события, восстановление второго шага после перезапуска с обрезанной историей, миграция v7 → v8,
сохранение задачи до первого ответа, независимые ветки, суммаризация и откат транзакции при ошибке записи.
