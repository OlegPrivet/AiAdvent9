# День 15: контролируемые переходы состояний

Основа: `week3_stream6_slides/week3_stream6_summary_and_transcript.md`, раздел 4; слайды 18–20. Режим задачи использует
жизненный цикл `planning → execution → validation → done` и проверяет переходы программным кодом.

## Разрешённые переходы

| Текущее состояние | Следующее состояние | Условие                                                                     |
|-------------------|---------------------|-----------------------------------------------------------------------------|
| `planning`        | `execution`         | Пользователь утвердил готовый план через `/task approve`                    |
| `execution`       | `validation`        | Последовательно завершены все шаги утверждённого плана                      |
| `execution`       | `planning`          | Агент указал непустую причину пересмотра; новый план нужно утвердить заново |
| `validation`      | `execution`         | Проверка выявила замечания и добавила шаги исправления                      |
| `validation`      | `done`              | Проверка успешно завершена                                                  |

Из `done` переходов нет. Пауза не меняет этап, утверждение плана или уже сохранённые результаты. Модель предлагает
операцию, а контроллер задачи принимает или отклоняет её до сохранения и показа ответа.

## Проверка полного цикла

Установите актуальную версию команды и запустите её с настроенным `NEURALDEEP_API_KEY`:

```bash
cargo install --path .
agi
```

Внутри `agi` начните задачу:

```text
/task start Подготовь описание сервиса заметок: требования, REST API и проверку согласованности.
```

После построения плана `/task` должен показывать `planning` и ожидание `/task approve`. Ассистент не начинает шаги
реализации самостоятельно. Выполните:

```text
/task approve
```

После утверждения агент последовательно выполняет шаги, переходит в `validation` и только после успешной проверки — в
`done`. Ответ каждого этапа появляется в истории после проверки перехода и успешного сохранения состояния.

## Недопустимые переходы и пауза

Автоматические тесты подменяют ответ модели и проверяют попытки выполнить `validation_passed` из `planning`, составить
новый план из `execution` и завершить задачу до выполнения всех шагов. Контроллер должен:

1. Отклонить операцию с сообщением о текущем этапе и ожидаемом действии.
2. Не показать и не записать непроверенный текст ответа.
3. Сохранить последний корректный прогресс и поставить задачу на паузу.
4. Продолжить с той же границы после `/task resume`.

Для ручной проверки паузы остановите выполнение через Ctrl+C или `/task pause`, выполните `/exit`, затем восстановите
чат командой `agi --restore <UUID>`. После восстановления состояние остаётся на паузе. `/task resume` повторяет только
текущий незавершённый этап; завершённые шаги не запускаются заново. Если пауза произошла после готового плана, сначала
по-прежнему требуется `/task approve`.

## Автоматические проверки

Тесты используют локальный HTTP mock и не требуют внешней сети или настоящего API-ключа:

```bash
cargo test
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
```

Покрыты таблица операций для каждого этапа, запрет пропуска этапов, скрытие отклонённого ответа в REPL и TUI, атомарное
сохранение результата, пауза, перезапуск и продолжение со следующего незавершённого шага.
