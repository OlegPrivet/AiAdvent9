# FAQ поддержки agi

## HTTP 404 при подключении собственной модели

Для собственного OpenAI-совместимого сервера укажите базовый URL API, например `http://localhost:8000/v1`. Клиент добавляет к нему `/chat/completions`. Если сервер обслуживает API по `/v1`, адрес без `/v1` приведёт к запросу по неверному пути. Проверьте адрес в `/llm` и настройки маршрутов сервера. Не запускайте и не скачивайте модели: их жизненным циклом управляет пользователь.

## Отсутствует ключ NeuralDeep

Для запросов к NeuralDeep задайте `NEURALDEEP_API_KEY` в окружении процесса agi. Переменная, заданная в одной вкладке терминала, может отсутствовать в другой. После изменения окружения запустите agi из той же вкладки. Никогда не отправляйте поддержке значение ключа. Для собственных HTTP-профилей ключ NeuralDeep не требуется; эмбеддинги имеют отдельное подключение.

## Обычный чат работает, инструменты недоступны

Для автоматических вызовов MCP-инструментов и делегирования главная LLM должна поддерживать tools. Проверьте возможности сервера и флаг поддержки tools в профиле `/llm`. Установка флага сама по себе не добавляет поддержку серверу. Если сервер не поддерживает tools, выберите подходящий уже настроенный профиль. Успешное подключение к MCP не доказывает поддержку tools моделью.

## Ошибка подключения MCP

В `/mcp` откройте сервер и выполните проверку подключения. Для stdio проверьте исполняемый файл, аргументы и рабочий каталог. Для HTTP проверьте адрес MCP endpoint и наличие требуемой переменной окружения с токеном. Не передавайте токены в переписке. Если проверка успешна, сообщите точную ошибку вызова и имя инструмента.

## Пустой индекс RAG или нет подходящих документов

Документы добавляются явно: `agi rag add PATH`. Проверьте список через `agi rag list`, обновляйте ранее добавленные документы командой `agi rag refresh`. Индексация и поиск используют настроенный сервис эмбеддингов. Отсутствие подходящих фрагментов не подтверждает причину проблемы; уточните текст ошибки и добавьте соответствующую документацию.
