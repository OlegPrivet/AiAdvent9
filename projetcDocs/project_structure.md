# Структура проекта agi

`agi` — Rust CLI для общения с NeuralDeep и пользовательскими OpenAI-совместимыми LLM. Исходники находятся в `src`, интеграционные CLI-тесты — в `tests`, документация — в `projetcDocs`. Название каталога документации сохраняется с существующим написанием. Cargo.toml описывает зависимости, Cargo.lock фиксирует их версии.

## Запуск и интерфейсы

`src/main.rs` подключает модули, разбирает аргументы и выбирает команду или интерфейс. `src/cli.rs` описывает аргументы запуска и подкоманды `llm`, `rag`, `review`, `release` и `support-server`. В интерактивном терминале работает полноэкранный TUI; для построчного ввода используется REPL.

`src/repl.rs` обрабатывает вопросы и slash-команды в REPL. `src/tui.rs` управляет редактором, меню, фоновыми запросами и событиями полноэкранного интерфейса. `src/input.rs` отвечает за ввод и историю команд, `src/ui.rs` — за вывод и Markdown. `src/settings.rs` хранит настройки чата; `src/config.rs` централизует сервисные значения по умолчанию.

## Агент и LLM API

Путь обычного вопроса: CLI → REPL или TUI → подготовка контекста и RAG → главный агент → LLM API → ответ и сохранение чата.

`src/agent.rs` реализует главного агента: формирование сообщений, потоковый ответ, делегирование, вызовы MCP, проверку инвариантов и строгие RAG-ответы. `src/agent_catalog.rs` хранит определения дочерних агентов, `src/agents_ui.rs` предоставляет управление каталогом.

`src/api.rs` реализует HTTP/SSE и OpenAI-совместимый протокол запросов, ответов и tool-calling. `src/llm.rs` хранит подключения LLM и общий выбор модели; `src/llm_ui.rs` предоставляет меню подключения. Пользователь управляет своими модельными серверами. Клиент не скачивает и не запускает модели. API-описание NeuralDeep и контракты клиента находятся в `projetcDocs/llm_docs.md`.

## Чаты, память и задачи

`src/chat.rs` хранит чаты, сообщения, настройки, метрики, checkpoints и ветки диалога в SQLite `chats.sqlite3`. Каталог состояния: `$XDG_STATE_HOME/agi`, при отсутствии этой переменной на macOS/Linux — `~/.local/state/agi`. Ветки диалога доступны через `/branch` и не являются Git-ветками.

`src/context.rs` определяет стратегии истории и Sticky Facts. `src/memory.rs` управляет рабочей памятью и подключаемыми Markdown-профилями, решениями и знаниями. `src/summary.rs` реализует ручную суммаризацию. `src/task.rs` управляет сохранёнными задачами с этапами planning, execution, validation и done. `src/invariants.rs` хранит и проверяет глобальные правила. `src/metrics.rs` и `src/pricing.rs` отвечают за метрики и справочную стоимость.

## Документы и RAG

`src/rag.rs` реализует библиотеку документов, эмбеддинги, поиск и SQLite-индекс `rag.sqlite3` в каталоге состояния. `src/rag_extract.rs` извлекает текст; `src/rag_chunk.rs` разбивает его на фрагменты. `src/rag_pipeline.rs` выполняет поиск, фильтрацию, reranking и query rewrite. `src/rag_answer.rs` проверяет строгие ответы и цитаты; `src/rag_chat.rs` поддерживает RAG-диалог с памятью задачи. `src/rag_cli.rs` реализует команды управления библиотекой. Модули `rag_eval` и `rag_day23`–`rag_day25` реализуют оценочные сценарии.

Добавление README и документации выполняется через `agi rag add <пути>` или `/rag add <путь>`. Поиск включается в чате через `/rag on`; `/rag refresh` обновляет изменившиеся источники. Индекс общий для всех чатов. Поиск передаёт вопрос сервису эмбеддингов, выбирает фрагменты и добавляет их в контекст LLM вместе с источниками.

## MCP и помощь разработчику

`src/mcp.rs` хранит настройки MCP-серверов, подключается по stdio или Streamable HTTP, получает инструменты и вызывает их. `src/mcp_ui.rs` реализует меню `/mcp`. Главный агент получает инструменты всех включённых серверов и выбирает их по описаниям. Встроенный демонстрационный сервер `src/mcp_demo.rs` предоставляет только `echo`.

`src/project_help.rs` распознаёт `/help <вопрос>` и добавляет инструкции ассистента разработчика. Команда использует документацию при `/rag on`, историю чата и доступные MCP-инструменты; `/help` без вопроса выводит справку. Запрос о проекте выполняется отдельно от шагов текущей задачи. Для получения текущей Git-ветки пользователь подключает соответствующий MCP-сервер. Текущее состояние Git нельзя определить по сохранённой документации.

## Подготовка описания релиза

`src/release.rs` реализует `agi release prepare --from REF --to REF --output DIRECTORY`.
Команда разрешает Git-ссылки в SHA и использует `src/review_git.rs` для чтения зафиксированных изменений
и фильтрации файлов. Диапазон коммитов и diff передаются активной LLM из общего каталога одним обычным
запросом без tools, RAG и истории чата. Результат — `RELEASE_NOTES.md` и `release.json` со статусом `draft`,
SHA, ограничениями и метриками. Существующие результаты не перезаписываются. Тесты, сборка и публикация
выпуска не запускаются. Проверки сценария находятся в `src/release_tests.rs` и `tests/cli_release.rs`.

## Проверки

Unit-тесты расположены рядом с модулями, интеграционные тесты запускают CLI из `tests`. HTTP-проверки используют локальные mock-серверы; реальная LLM и API-ключ не нужны. Основные команды: `cargo test`, `cargo fmt --all -- --check`, `cargo clippy --all-targets --all-features -- -D warnings`.
