# День 22 — проверка RAG через интерфейс `agi`

Набор [`day22_rag_eval.json`](day22_rag_eval.json) содержит 10 вопросов. Для каждого указаны ожидаемый ответ и нужный
источник. Проверка доступна в обычном и полноэкранном интерфейсе `agi`.

## Подготовка документов

Откройте `agi` из корня этого проекта с настроенным `NEURALDEEP_API_KEY`. Вводите следующие команды **внутри
приложения**, по одной строке:

```text
/rag add README.md
/rag add projetcDocs/invariants_testing.md§
/rag add projetcDocs/llm_docs.md
/rag add projetcDocs/memory_layers.md
/rag add projetcDocs/memory_testing.md
/rag add projetcDocs/task_state_testing.md
/rag add projetcDocs/task_transitions_testing.md
/rag status
```

`/rag status` должен показать 7 источников и непустой индекс `structure`. Уже добавленные документы можно посмотреть
через `/rag list`. Другие документы в общей библиотеке могут повлиять на поиск; для воспроизводимого сравнения оставьте
только эти семь.

Если используете локальный сервис эмбеддингов, сначала настройте его прямо в `agi` командой
`/rag embeddings set URL MODEL`, затем добавьте документы. После смены сервиса или модели выполните `/rag reindex`.
Модель ответов вызывается через NeuralDeep отдельно от эмбеддингов.

## Запуск сравнения

Введите в `agi`:

```text
/rag evaluate
```

Команда задаст все 10 вопросов модели дважды: в новом пустом чате без RAG и в новом пустом чате с найденными
фрагментами. Оба ответа и найденные источники появятся в отчёте внутри приложения. В полноэкранном интерфейсе листайте
отчёт стрелками или `PgUp`/`PgDn`, закройте `Esc`. Открыть его снова можно командой `/rag report`.

Отчёт также сохраняется в каталоге состояния `agi` как `day22_rag_answers.md`. Проверка делает 20 запросов к модели
ответа и 10 запросов к модели эмбеддингов, помимо загрузки документов. В полноэкранном интерфейсе `Ctrl+C` отменяет
проверку. Если она завершилась ошибкой, исправьте указанную причину и запустите `/rag evaluate` повторно.

## Вопросы для ручной проверки

Для каждого вопроса сначала выполните `/clear`, `/rag off` и задайте вопрос. Затем снова выполните `/clear`,
`/rag on` и задайте **тот же** вопрос. Так ответы не повлияют друг на друга через историю чата. Повторите для всех
10 вопросов:

1. Какая переменная окружения нужна для API-ключа agi?
2. Как восстановить сохранённый чат по UUID при запуске?
3. Как подключить локальный stdio MCP-сервер?
4. Какие три слоя памяти есть у агента?
5. Что происходит при недопустимом переходе состояния задачи?
6. Как ассистент должен реагировать на конфликт с глобальными инвариантами?
7. Какой API и модель используются для векторизации документов?
8. Где хранятся долгосрочные знания агента?
9. Где хранится локальный индекс RAG и отделён ли он от истории чатов?
10. Что нужно сделать с индексом RAG после смены модели эмбеддингов или URL сервиса?

Ожидаемые факты и нужные файлы для каждого вопроса записаны в [`day22_rag_eval.json`](day22_rag_eval.json).

## Оценка результатов

Для каждого вопроса в отчёте сравните оба ответа с полем «Ожидание»: **2** — все основные факты верны, **1** — ответ
частичный, **0** — нужных фактов нет или есть существенная ошибка. Сложите баллы для каждого режима; максимум — 20.

Для ответа с RAG дополнительно проверьте, найден ли нужный файл и есть ли в самом тексте ответа ссылка `[n]` на его
фрагмент. Автоматически добавленный список «Найденные источники» не считается ссылкой модели. Запишите случаи ошибки
поиска отдельно от случаев, когда фрагмент найден, но ответ неверен. Итог задания — две суммы баллов, число корректных
ссылок и 2–3 примера различий ответов.
