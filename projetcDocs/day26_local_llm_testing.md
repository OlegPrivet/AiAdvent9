### 2. Средняя сложность

Запрос: Объясни ownership и borrowing в Rust. Покажи короткий пример с неизменяемой ссылкой и объясни, почему исходная строка остаётся доступной.

Полное время CLI: 24.09 с; код завершения: 0.

Ответ модели, без исправлений:

В Rust, `ownership` и `borrowing` (производительство) - это системы, которые гарантируют память безопасность и предотвращают некорректные доступы к данным.

1. **Ownership**: Каждый значимый тип в Rust имеет единственного владельца в любой момент времени. Когда владелец выходит из действия, его значение будет уничтожен. Это гарантирует, что никогда не существуют устаревших ссылок на данные, что может привести к непредсказуемости и ошибкам.

2. **Borrowing**: Borrowing позволяет другим частям кода временно получать доступ к данным, не передавая им владение. В Rust, это реализовано с помощью двух типов ссылок:
   - `&const T` (неизменяемая ссылка на значение типа T)
   - `&mut T` (изменяемая ссылка на значение типа T)

Пример:

```rust
fn main() {
    let s = String::from("hello"); // s владелец строки "hello"

    // Создаем неизменяемую ссылку на s
    let r1 = &s; // r1 теперь неизменяемая ссылка на s

    // Создаем изменяемую ссылку на s
    let r2 = &mut s; // r2 теперь изменяемая ссылка на s

    // Изменяем значение через изменяемую ссылку
    r2.push_str(" world");

    // Отображаем значение
    println!("{}{}", r1, r2); // Вывод: hello world
}
```

В этом примере, `s` - это владелец строки "hello". Мы создаем две ссылки `r1` и `r2` на `s`. `r1` - неизменяемая ссылка, а `r2` - изменяемая. Когда мы изменяем значение `s` через `r2`, `r1` остается доступной, потому что она не изменяет содержимое `s`. Она просто делает неизменяемый доступ к нему.

Эта система `ownership` и `borrowing` в Rust помогает предотвратить многие типы ошибок, связанных с неправильным использованием памяти, такие как использование устаревших ссылок, двойных удаления и деления на нулевую.

### 3. Сложный запрос

Запрос: Напиши функцию на Rust, которая удаляет дубликаты из Vec<i32>, сохраняя порядок первого появления. Используй HashSet, объясни временную и пространственную сложность и приведи пример входа и результата.

Полное время CLI: 16.46 с; код завершения: 0.

Ответ модели, без исправлений:

Вот функция на Rust, которая удаляет дубликаты из `Vec<i32>`, сохраняя порядок первого появления:

```rust
use std::collections::HashSet;

fn remove_duplicates(input: Vec<i32>) -> Vec<i32> {
    let mut seen = HashSet::new();
    let mut result = Vec::new();

    for &item in &input {
        if seen.insert(item) {
            result.push(item);
        }
    }

    result
}
```

В этом коде мы используем `HashSet` для хранения уже встреченных элементов. `HashSet::insert()` возвращает `true`, если элемент был добавлен в HashSet, иначе `false`. Это позволяет нам определить, был ли элемент новым или уже встреченным.

**Временная сложность:** Обработка каждого элемента в входном векторе занимает O(1) времени, так как HashSet имеет среднюю константу O(1) для операций вставки и поиска. Поэтому общая временная сложность функции равна O(n), где n - длина входного вектора.

**Пространственная сложность:** Максимальное использование памяти происходит при хранении элементов в HashSet и результирующем векторе. В хорошем случае, пространственная сложность будет O(n), где n - длина входного вектора.

**Пример входа и результата:**

Вход:
```rust
let input = vec![1, 2, 3, 2, 4, 1, 5, 6, 3]
```

Результат:
```rust
let output = remove_duplicates(input);
println!("{:?}", output); // [1, 2, 3, 4, 5, 6]
```

В этом примере функция удаляет дубликаты из входного вектора, сохраняя порядок первого появления элементов.
