# День 24 — источники, цитаты и «не знаю»

## Подготовка

Соберите текущую версию: `cargo build`. Ключ для генерации, reranker и судьи передавайте только через
`NEURALDEEP_API_KEY`. Автоматические Rust-тесты используют локальные mock-серверы и не требуют ключа.

Для отдельного эксперимента задайте `XDG_STATE_HOME` на новый временный каталог до запуска `agi`. Все команды
эксперимента должны использовать один и тот же каталог. Это исключает посторонние документы из поиска.

## Ручная проверка в REPL или TUI

```text
/clear
/rag on
/rag strict on
/rag status
Где хранится локальный индекс RAG и отделён ли он от истории чатов?
```

Включение strict при фильтре off выбирает similarity с текущим порогом (изначально 0.35). Уже выбранный rerank
сохраняется. Порог включительный: равная порогу оценка проходит. Similarity и rerank имеют отдельные шкалы и пороги.

Ожидаемый вид успешного ответа (идентификаторы и цитаты зависят от индекса):

```text
Ответ:
Индекс находится в rag.sqlite3 отдельно от истории чатов [1].

Источники:
[1] /путь/README.md · Документы и RAG · chunk_id <реальный идентификатор>

Цитаты:
[1] «реальный дословный фрагмент из найденного чанка»
```

Каждая цитата должна присутствовать в указанном чанке. Приложение проверяет непрерывную подстроку с нормализацией
пробелов; показывает исходный текст. source и section подставляются из индекса. Только использованные источники
попадают в ответ. Смысл ответа проверяйте отдельно: подлинная цитата сама по себе не доказывает утверждение.

В strict окончательный ответ появляется после проверки, без промежуточных дельт. Режим имеет приоритет над обычным
JSON-форматом из `/settings`, пользовательская stop sequence для финальной строгой генерации не применяется.
Выбранные модель, температура и max_tokens сохраняются. Повреждённый или обрезанный ответ, ложная цитата и ссылка
разрешают одну попытку исправления. Повторная ошибка является технической ошибкой, ответ не сохраняется.
Исправление по инвариантам также проходит проверку цитат и повторную проверку инвариантов.

## Отказ при недостаточном контексте

```text
/rag filter similarity
/rag rewrite off
/rag threshold similarity 1
/rag search Какой SLA гарантирует agi для восстановления rag.sqlite3 после аварии сервера?
Какой SLA гарантирует agi для восстановления rag.sqlite3 после аварии сервера?
```

Если итоговый контекст пуст, приложение без генерации, MCP и дочерних агентов возвращает:

```text
Не знаю: в найденных документах недостаточно подтверждений для ответа.

Уточните, о каком документе или разделе идёт речь?
```

Затем верните `/rag threshold similarity 0.35`. Проверьте ещё вопрос: «Какой точный бюджет в рублях утверждён для
проекта agi на 2030 год?». Если найденные чанки проходят порог, но не содержат ответа, модель должна выбрать unknown.
Отказ не содержит источников и цитат и не продвигает состояние задачи. Ошибки API не маскируются под «не знаю».

`/rag filter off` при включённом strict отклоняется. `/rag strict off` разрешает прежний формат, сохраняя фильтр;
при необходимости выполните `/rag filter off`. `/rag off` отключает применение RAG, сохраняя настройки.
Настройки восстанавливаются с чатом, checkpoint и веткой. Старые чаты имеют strict off.

## Оценка 10 вопросов

```text
/rag evaluate day24
/rag report day24
```

Из shell:

```bash
agi rag evaluate --suite day24 --eval projetcDocs/day24_rag_eval.json \
  --report projetcDocs/day24_rag_answers.md
```

Набор включает ровно 10 вопросов с ответами в корпусе и 2 дополнительных отрицательных случая. Для каждого создаётся
пустой чат: strict on, structure, top-K 12 → 4, rerank 0.50, rewrite off, температура 0, модель по умолчанию,
max_tokens 10000. Настройки текущего пользовательского чата на эксперимент не влияют. Таймаут генерации и каждой
попытки исправления — 120 секунд; судьи — 60 секунд. Ошибка reranker не переключает фильтр.

Отчёт сохраняет SHA-256 набора и файлов корпуса, итоговый контекст и оценки retrieval, ответ, цитаты, метаданные,
число исправлений, время и фактический usage. Десять основных вопросов учитываются отдельно от отрицательных.
Судья сравнивает ответ с эталоном, а подтверждение утверждений — только с приведёнными цитатами. Ошибка судьи означает
отсутствие оценки. Ошибки поиска и генерации не засчитываются как успешные ответы.

Отчёт сохраняется атомарно после каждого вопроса. В TUI `Ctrl+C` отменяет оценку; `/rag report day24` открывает
частичный результат, который помечен соответствующим статусом. Оценка с API-ошибками завершается ошибкой и сохраняет
отчёт. Раздел ручной проверки нужно заполнить после чтения ответов и цитат.

Критерий результата: источники и подлинные цитаты в 10/10 основных ответах, все существенные факты подтверждены
цитатами по ручной проверке; оба отрицательных случая дают отказ с уточнением. Результаты судьи и расхождения
с ручной проверкой фиксируются без подмены фактических оценок.

## Явный подбор порога для корпуса

Порог reranker в оценке можно задать отдельно от настроек чата:

```text
/rag evaluate day24 --rerank-threshold 0.20
```

```bash
agi rag evaluate --suite day24 --eval projetcDocs/day24_rag_eval.json \
  --report projetcDocs/day24_rag_answers.md --rerank-threshold 0.20
```

Без аргумента остаётся порог 0.50. Для данного корпуса он отсёк подтверждения ответов об инвариантах и долгосрочной
памяти: полезные кандидаты получили оценки около 0.21 и 0.33. Проверка с порогом 0.20 является отдельным экспериментом,
а не заменой исходных результатов или универсальной рекомендацией. Порог подобран по этому набору; независимая
оценка на новых вопросах требует отдельного набора. Параметры чатов и сервисные значения по умолчанию не изменяются.
